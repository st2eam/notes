# 简单工厂模式
> 创建型型设计模式

简单工厂模式 ## 介绍 简单工厂 （Simple Factory）模式也称作静态工厂方法（Static Factory Method）模式，其核心是由一个工厂根据不同条件生产不同类型的对象。从命名上来看就知道这种模式足够简单。 ## 结构 工厂类：本模式的核心，主要的业务逻辑可能在这里实现，并通过参数创建不同的具体产品角色。 抽象产品：指具体产品继承的父类或实现的接口。 具体产品：工厂类所创建的具体产品对象。 ## 问题 假设我们现在需要迭代【 数据报表模块 】这个功能，最初只有【 报表分析 】这个功能，里面和【 报表分析 】这款产品做了强耦合。 AI 数据问答 数据报表模块-执行中 由于【 报表分析 】不对现有表格进行修改操作。因此现在要利用现在的对话框，在里面添加一个【 操作表格模块 】功能。经过分析，很多大的流程上是相同的，都有【提问-&gt;上传数据-&gt;系统返回结果-&gt;使用/废弃-&gt;完成】的流程，只是一些功能方面有差异。 AI 操作表格模块 表格操作模块-执行中 由于之前的代码中已经和【 报表分析 】做了强绑定，如果要重用之前的这部分代码，稍加修改还可以勉强使用。 ## 解决方案 简单工厂 模式 描述了一个类， 它拥有一个包含大量条件语句的构建方法， 可根据方法的参数来选择对何种产品进行初始化并将其返回。 子功能接口（Product） interface IPlugin { /** * 获取过滤问题 * @param filter 过滤器，根据过滤字段搜素 */ getFilterQuestion(filter:string): Question[] /** * 获取推荐问题，预设在子插件中 * 返回3个简单和1个高级问题 */ getRecommendQuestion(): Question[] /** * 设置小组件的状态监听 * 传undefined表示取消监听 */ setPluginListener(listener: IPluginListener|undefined): void /** * 请求问题 * @param question 需要问的问题 * @param intention 意图 */ requestQuestion(question: string, intention: IntentCode | undefined) : void /** * 停止请求 */ stop():void } 子功能管理器接口 （Factory） class PluginFactory { /**安装plugin * @param type 功能类型 * @param plugin plugin实例 */ static createPlugin(type: FeatureCode): IPlugin{ // 工厂类里用switch语句控制生产哪种商品； // 使用者只需要调用工厂类的静态方法就可以实现产品类的实例化。 switch (type){ case &quot;SPREADSHEET&quot;: return new SpreadsheetOperator(); case &quot;REPORT&quot;: return new ReportAnalysis(); default: return new DefaultChat(); } } } } ## 优缺点 ✔️ 实现简单 ：逻辑清晰，易于实现。 ✔️ 集中管理 ：所有产品的创建逻辑集中在一个地方，便于查看和修改。 ❌ 扩展性差 ：每次新增产品类型都需修改工厂类，违反开闭原则。 ❌ 单一责任原则 ：工厂类承担过多职责，增加了维护难度。 ❌ 不利于多态性 ：所有产品的逻辑紧耦合，难以实现多态性。 🔗 和其他工厂模式的区别 简单工厂 ： 使用一个工厂对象用来生产同一等级结构中的任意产品。（不支持拓展增加产品） 工厂方法 ： 使用多个工厂对象用来生产同一等级结构中对应的固定产品。（支持拓展增加产品） 抽象工厂 ： 使用多个工厂对象用来生产不同产品族的全部产品。（不支持拓展增加产品；支持增加产品族） 在绝大多数情况下， 简单工厂是引入 工厂方法 或 抽象工厂 模式时的一个中间步骤。 ## 实战示例 这是一个 // charts解析工厂类 import { ChartType } from &quot;@/lib/charts import LineChartParser from &quot;@/lib/charts import BarChartParser from &quot;@/lib/charts import PieChartParser from &quot;@/lib/charts import ScatterChartParser from &quot;@/lib/charts import RadarChartParser from &quot;@/lib/charts class ChartParserFactory { createParser(type?: ChartType) { switch (type) { case ChartType.LINE: return new LineChartParser();
