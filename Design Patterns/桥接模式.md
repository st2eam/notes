# 桥接模式
> 结构型型设计模式

桥接模式 ## 介绍 桥接模式 是一种结构型设计模式， 可将一个大类或一系列紧密相关的类拆分为抽象和实现两个独立的层次结构， 从而能在开发时分别使用。 ## 结构 抽象部分 （Abstraction） 提供高层控制逻辑， 依赖于完成底层实际工作的实现对象。 实现部分 （Implementation） 为所有具体实现声明通用接口。 抽象部分仅能通过在这里声明的方法与实现对象交互。 抽象部分可以列出和实现部分一样的方法， 但是抽象部分通常声明一些复杂行为， 这些行为依赖于多种由实现部分声明的原语操作。 具体实现 （Concrete Implementations） 中包括特定于平台的代码。 精确抽象 （Refined Abstraction） 提供控制逻辑的变体。 与其父类一样， 它们通过通用实现接口与不同的实现进行交互。 通常情况下， 客户端 （Client） 仅关心如何与抽象部分合作。 但是， 客户端需要将抽象对象与一个实现对象连接起来。 ## 问题 假如你正在开发一个应用，经过多次版本迭代，这个功能已经非常成熟。但这时，产品突然要求在客户端中也想加入这个功能。因此，你意识到你必须区分两端之间API的差异。 在实际的程序中， 抽象部分是图形用户界面 （GUI）， 而实现部分则是底层操作系统代码 （API）， GUI 层调用 API 层来对用户的各种操作做出响应。 在最糟糕的情况下， 程序可能会是一团乱麻， 其中包含数百种条件语句， 连接着代码各处不同种类的 GUI 和各种 API。 ## 解决方案 让我们试着用桥接模式来解决这个问题。该模式建议将类拆分为两个类层次结构： 抽象部分： 程序的 GUI 层。 实现部分： 操作系统的 API。 创建跨平台应用程序的一种方法 ## 与其他模式的关系 桥接模式 通常会于开发前期进行设计， 使你能够将程序的各个部分独立开来以便开发。 另一方面， 适配器模式 通常在已有程序中使用， 让相互不兼容的类能很好地合作。 你可以结合使用 生成器模式 和 桥接模式 ： 主管 类负责抽象工作， 各种不同的 生成器 负责 实现 工作。 ## 优缺点 ✔️ 你可以创建与平台无关的类和程序。 ✔️ 客户端代码仅与高层抽象部分进行互动， 不会接触到平台的详细信息。 ✔️ 开闭原则 。 你可以新增抽象部分和实现部分， 且它们之间不会相互影响。 ✔️ 单一职责原则 。 抽象部分专注于处理高层逻辑， 实现部分处理平台细节。 ❌ 对高内聚的类使用该模式可能会让代码更加复杂。 ## 实战示例 多端适配插件 一个多端适配的插件，需要分别在pc端和web端执行，这时就会涉及到公共逻辑和差异逻辑 IProxy.ts export default interface IProxy { // 获取范围内非空单元格总数 getCellCount(range: IRange, sheet?: any): Promise&lt;number&gt; // 获取单元格数据 getCellData(row: number, col: number, sheet?: any): Promise&lt;string&gt; // 设置单元格数据 setCellData(row: number, col: number, value: string, sheet?: any): void } WebProxy.ts class WebProxy implements IProxy { getCellCount() getCellData() setCellData() } WpsProxy.ts class WpsProxy implements IProxy { getCellCount() getCellData() setCellData() } ProxyAdaptor.ts import IProxy from &quot;./IProxy&quot; class ProxyAdaptor { private proxy: IProxy | undefined getProxy():IProxy | undefined { return this.proxy; } setProxy(proxy:IProxy) { this.proxy = proxy } } export default new ProxyAdaptor()
