# 解释器模式

> 行为设计模式

## 介绍

解释器模式（Interpreter Pattern）给定一个语言，定义它的文法的一种表示，并定义一个解释器，这个解释器使用该表示来解释语言中的句子。

简单来说：**为某种特定"语言"定义一套语法规则，然后写一个解释器来执行这套规则**。

## 结构

| 角色 | 说明 |
|------|------|
| **抽象表达式（Abstract Expression）** | 声明一个抽象的解释操作 |
| **终结符表达式（Terminal Expression）** | 实现与文法中的终结符相关的解释操作（不可再分的原子规则） |
| **非终结符表达式（Non-terminal Expression）** | 为文法中的非终结符实现解释操作（可递归组合的规则） |
| **上下文（Context）** | 包含解释器之外的一些全局信息 |
| **客户端（Client）** | 构建抽象语法树，调用解释操作 |

## 问题

假设你需要处理一种自定义的查询语言，例如：

```
age > 18 AND (city = "北京" OR city = "上海")
```

你需要解析这种表达式，并能够对数据集合执行过滤。

## 解决方案

```typescript
// 上下文：数据
interface Context {
    [key: string]: any;
}

// 抽象表达式
interface Expression {
    interpret(context: Context): boolean;
}

// 终结符：比较运算
class CompareExpression implements Expression {
    constructor(
        private field: string,
        private operator: string,
        private value: any
    ) {}

    interpret(context: Context): boolean {
        const fieldValue = context[this.field];
        switch (this.operator) {
            case '>':  return fieldValue > this.value;
            case '<':  return fieldValue < this.value;
            case '=':  return fieldValue === this.value;
            case '>=': return fieldValue >= this.value;
            case '<=': return fieldValue <= this.value;
            default: throw new Error(`未知运算符: ${this.operator}`);
        }
    }
}

// 非终结符：AND 逻辑
class AndExpression implements Expression {
    constructor(private left: Expression, private right: Expression) {}
    interpret(context: Context): boolean {
        return this.left.interpret(context) && this.right.interpret(context);
    }
}

// 非终结符：OR 逻辑
class OrExpression implements Expression {
    constructor(private left: Expression, private right: Expression) {}
    interpret(context: Context): boolean {
        return this.left.interpret(context) || this.right.interpret(context);
    }
}

// 使用
const expr = new AndExpression(
    new CompareExpression('age', '>', 18),
    new OrExpression(
        new CompareExpression('city', '=', '北京'),
        new CompareExpression('city', '=', '上海')
    )
);

const data = { name: '小明', age: 25, city: '北京' };
console.log(expr.interpret(data)); // true
```

## 简化表达：字符串解析器

对于简单场景，可以直接写一个字符串表达式的解析器：

```typescript
function evaluateExpression(expr: string, data: Record<string, any>): boolean {
    // 替换变量
    let resolved = expr;
    for (const [key, value] of Object.entries(data)) {
        resolved = resolved.replace(new RegExp(`\\b${key}\\b`, 'g'), JSON.stringify(value));
    }
    // 执行 JavaScript 表达式
    try {
        return new Function(`return ${resolved}`)();
    } catch {
        throw new Error(`无效表达式: ${expr}`);
    }
}

// 使用
const rule = 'age > 18 && (city === "北京" || city === "上海")';
console.log(evaluateExpression(rule, { age: 25, city: '北京' })); // true
```

> ⚠️ 使用 `new Function` 或 `eval` 时要确保表达式来源可信，避免注入风险。

## 与其他模式的关系

| 模式 | 关系 |
|------|------|
| **组合模式** | 抽象语法树通常是组合模式的实例 |
| **享元模式** | 可以用来共享终结符表达式，减少内存占用 |
| **迭代器模式** | 解释器可以用迭代器遍历 AST 节点 |
| **访问者模式** | 可以在 AST 上运行访问者，实现如代码生成、格式化等操作 |

## 优缺点

✔️ **易于扩展**：通过新增表达式类即可扩展语法
✔️ **易于实现**：每种语法规则都对应一个类，结构清晰
✔️ 可以将复杂的语法规则分解为简单的表达式组合

❌ **执行效率低**：通常需要大量解释器对象和递归调用
❌ **维护复杂**：语法规则增多时，类数量急剧增长
❌ 不适合复杂的文法，此时应使用专门的解析器生成工具

## 实战示例

### SQL 查询构建器

```typescript
class QueryBuilder {
    private conditions: string[] = [];

    where(field: string, op: string, value: any): this {
        this.conditions.push(`${field} ${op} ${JSON.stringify(value)}`);
        return this;
    }

    and(): this {
        this.conditions.push('AND');
        return this;
    }

    or(): this {
        this.conditions.push('OR');
        return this;
    }

    build(): string {
        return this.conditions.join(' ');
    }
}

const sql = new QueryBuilder()
    .where('age', '>', 18)
    .and()
    .where('city', '=', '北京')
    .build();
// age > 18 AND city = "北京"
```

### 正则表达式引擎

正则表达式本身就是解释器模式的典型应用——你定义一个模式（语法），正则引擎解释这个模式并匹配文本。

### 模板引擎

Mustache、Handlebars 等模板引擎会在内部解析模板语法（如变量插值和条件块），然后解释执行。
