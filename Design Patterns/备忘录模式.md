# 备忘录模式
> 行为型设计模式

备忘录模式 亦称： 快照、Snapshot、Memento ## 介绍 备忘录模式 是一种行为设计模式， 允许在不暴露对象实现细节的情况下保存和恢复对象之前的状态。 ## 结构 原发器 （Originator） 类可以生成自身状态的快照， 也可以在需要时通过快照恢复自身状态。 备忘录 （Memento） 是原发器状态快照的值对象 （value object）。 通常做法是将备忘录设为不可变的， 并通过构造函数一次性传递数据。 负责人 （Caretaker） 仅知道 “何时” 和 “为何” 捕捉原发器的状态， 以及何时恢复状态。 负责人通过保存备忘录栈来记录原发器的历史状态。 当原发器需要回溯历史状态时， 负责人将从栈中获取最顶部的备忘录， 并将其传递给原发器的恢复 （restoration） 方法。 在该实现方法中， 备忘录类将被嵌套在原发器中。 这样原发器就可访问备忘录的成员变量和方法， 即使这些方法被声明为私有。 另一方面， 负责人对于备忘录的成员变量和方法的访问权限非常有限： 它们只能在栈中保存备忘录， 而不能修改其状态。 ## 问题 假设我们现在需要迭代【 表格工具集 】这个产品。需要添加【历史记录】的功能，需要保留每次对话框提问的所有历史记录。 历史记录 ## 解决方案 得益于之前 工厂模式 的修改，我们很容易将每次生成的结果保留下来，参照 备忘录模式 的结构，我们已经有了 IPluginManager - Caretaker IPluginBinder - Originator 现在我们只需要构造一个 Memento 就可以了。 小组件实例（Originator） interface IPluginBinder { // do something } 历史记录快照（Memento） interface IPluginHistory extends IPluginBinder{ // 快照相关信息 index:number binder:IPluginBinder // 问题 Question:Question // 完成状态 isFinish:boolean // 挂载状态 isMounted: boolean // 点赞点踩状态获取 setItem(key: string, value: any): void getItem(key: string): any // 功能相关 removeListener(): void setContainer(container: HTMLDivElement): void } 子功能管理器接口（ Caretaker ） interface IPluginManager { /**历史结果 关闭后清除 */ history: IPluginHistory[] ... } ## 与其他模式的关系 你可以同时使用 命令模式 和 备忘录模式 来实现 “撤销”。 在这种情况下， 命令用于对目标对象执行各种不同的操作， 备忘录用来保存一条命令执行前该对象的状态。 你可以同时使用 备忘录 和 迭代器模式 来获取当前迭代器的状态， 并且在需要的时候进行回滚。 有时候 原型模式 可以作为 备忘录 的一个简化版本， 其条件是你需要在历史记录中存储的对象的状态比较简单， 不需要链接其他外部资源， 或者链接可以方便地重建。 ## 优缺点 ✔️ 你可以在不破坏对象封装情况的前提下创建对象状态快照。 ✔️ 你可以通过让负责人维护原发器状态历史记录来简化原发器代码。 ❌ 如果客户端过于频繁地创建备忘录， 程序将消耗大量内存。 ❌ 负责人必须完整跟踪原发器的生命周期， 这样才能销毁弃用的备忘录。 ## 实战示例 编辑器 文本编辑器常常需要实现撤销和重做功能，备忘录模式可以存储文本的不同状态（如不同的版本），用户可以通过这些备忘录轻松恢复到之前的文本状态。 表单编辑 在用户填写表单时，可以使用备忘录模式来保存用户的输入状态。用户可以在填写过程中随时撤销到之前的状态，避免误操作导致的数据丢失。 游戏存档 在游戏中，玩家可以随时保存游戏状态（如角色位置、状态、物品等），使用备忘录模式将这些状态保存为备忘录，以便在需要时恢复到保存的状态。
