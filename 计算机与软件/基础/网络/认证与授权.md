# HTTP、认证与授权

> 前置：[HTTP](/%E8%AE%A1%E7%AE%97%E6%9C%BA%E4%B8%8E%E8%BD%AF%E4%BB%B6/%E5%9F%BA%E7%A1%80/%E7%BD%91%E7%BB%9C/HTTP.md)、[HTTP Cookie](</%E8%AE%A1%E7%AE%97%E6%9C%BA%E4%B8%8E%E8%BD%AF%E4%BB%B6/%E5%9F%BA%E7%A1%80/%E7%BD%91%E7%BB%9C/HTTP%20Cookie.md>)。目标：区分“你是谁”“你能做什么”，画出一次受保护请求的数据流。最后核对：2026-09-29。

浏览器请求 AI 服务时，前端不能替服务端决定数据权限。服务端要验证身份、判断资源归属，然后才检索笔记或调用工具。

## 一次请求的边界

~~~text
浏览器 --HTTPS--> 服务端
                    1. 验证会话或令牌（认证）
                    2. 判断能否读取这篇笔记（授权）
                    3. 查询数据并记录必要的审计信息
                    4. 返回最小必要数据
~~~

认证回答“请求者是谁”；授权回答“这个请求者能否执行该动作”。登录成功不意味着可以访问其他人的笔记。HTTP 状态码中，401 通常表示需要有效认证，403 表示身份已知但权限不足；实际返回还要避免泄露敏感资源是否存在。

Cookie 会话适合浏览器场景。生产环境的会话 Cookie 通常设置 Secure、HttpOnly 和合适的 SameSite 策略；写入操作还需考虑 CSRF。CORS 管的是浏览器能否读取跨源响应，不是服务端授权机制。所有敏感请求都必须经 HTTPS；令牌和密钥不放在公开网页或仓库中。

下面是**可运行的 Python 权限规则示例**，展示在数据访问前检查资源归属：

~~~python
def can_read_note(request_user_id: int | None, owner_id: int, is_public: bool) -> bool:
    if is_public:
        return True
    return request_user_id is not None and request_user_id == owner_id

assert can_read_note(7, 7, False)
assert not can_read_note(8, 7, False)
assert can_read_note(None, 7, True)
~~~

这个函数只是规则核心；真实服务还必须安全地验证会话、从数据库读取真实 owner_id，并在每个入口执行检查。OAuth/OIDC 用于委托授权与身份联合时，需要验证发行者、受众、过期时间和回调状态，不能只解析令牌内容。

参考：[MDN HTTP 指南](https://developer.mozilla.org/en-US/docs/Web/HTTP)、[MDN Cookie 安全](https://developer.mozilla.org/en-US/docs/Web/HTTP/Cookies)、[OWASP 授权速查](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。
