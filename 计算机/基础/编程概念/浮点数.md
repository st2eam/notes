# 浮点数

浮点数用有限位数保存有效数字和指数，表示近似的数值。二进制浮点数的形式类似于二进制科学计数法，可以覆盖较大的数量范围，但不能精确表示所有实数。

## JavaScript Number

JavaScript 的 `Number` 使用 IEEE 754 的 binary64 格式，共 64 位：1 位符号、11 位指数和 52 位显式小数部分。正规数还包含隐含的最高有效位，因此有效精度为 53 个二进制位。

53 位有效精度不等于“所有小数都有 53 位精度”，也不意味着小数点后固定位数精确。数值越大，相邻可表示数之间的间隔通常越大。

## 小数舍入误差

十进制的 0.1、0.2 在二进制中是无限循环小数，存入 `Number` 时必须舍入。计算结果因此可能偏离精确的十进制结果：

```js
0.1 + 0.2;         // 0.30000000000000004
0.1 + 0.2 === 0.3; // false
```

比较近似数值时，应根据数据规模和业务要求选择误差容限：

```js
function nearlyEqual(a, b, absTol = 1e-12, relTol = 1e-12) {
    if (a === b) return true;
    if (!Number.isFinite(a) || !Number.isFinite(b)) return false;
    return Math.abs(a - b) <= Math.max(
        absTol,
        relTol * Math.max(Math.abs(a), Math.abs(b))
    );
}

nearlyEqual(0.1 + 0.2, 0.3); // true
```

示例中的容限需要按场景调整。`Number.EPSILON` 表示 1 附近的相邻可表示数间隔，不能直接作为所有数值规模下的通用容限。

## 安全整数

`Number` 的安全整数范围为 $-(2^{53}-1)$ 到 $2^{53}-1$。超出范围后，有些整数仍能精确表示，但相邻整数可能被舍入成同一个值：

```js
const limit = Number.MAX_SAFE_INTEGER; // 9007199254740991
limit + 1 === limit + 2;               // true
```

需要精确表示大整数时，可以使用 `BigInt`。它只处理整数，不能直接表示小数，也不能与 `Number` 混合做普通算术运算。金额等十进制精确计算通常需要整数单位或专门的十进制运算方案。

## 特殊值

IEEE 754 还定义了无穷大、`NaN` 和带符号的零。在 JavaScript 中：

```js
1 / 0;             // Infinity
0 / 0;             // NaN
Number.isNaN(0/0); // true
```

因此，数学表达式转换成程序后，还需要检查精度、溢出和特殊值的处理方式。
