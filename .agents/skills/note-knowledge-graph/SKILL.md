---
name: note-knowledge-graph
description: 为当前笔记仓库新增或导入的笔记自动提取核心概念和关键词，复用知识图谱中的相关节点，创建缺失概念节点并建立可验证的关联。在新增笔记、整理资料为笔记或批量导入笔记时使用。
---

新添加笔记的记得关联知识图谱，请自动识别笔记内容中的核心概念和关键词，并将其与知识图谱中已有的相关节点建立关联。如果知识图谱中不存在对应节点，请创建新的节点后再建立关联。

1. 阅读新笔记全文，提取其主要讨论的概念、术语和关键词。忽略泛化词、偶然提及的词和代码示例中的无关标识符；所有关联都应有正文依据。
2. 检查 `.vitepress/vault/build.mjs`、`.vitepress/vault/model.mjs` 和同主题笔记的现有格式。本仓库以 Markdown 笔记作为节点，以正文链接和 frontmatter `relations` 作为边，图谱从源文件生成；不要单独维护节点或边的数据副本。
3. 搜索现有笔记的标题、路径、`aliases`、`tags` 和正文，结合含义判断匹配。优先复用同义词、缩写或别名对应的节点；同名异义概念使用明确的完整路径，不要仅凭关键词重合建立关系。
4. 缺失的核心概念在最合适的现有主题目录创建独立 Markdown 笔记，包含清晰标题、简短定义、与原笔记有关的解释和来源。只写有依据的内容，不创建空占位节点；为常用同义词或缩写添加 `aliases`。新概念节点不递归扩展为无关概念网络。
5. 将新笔记关联到匹配或新建的节点。正文自然引用使用 `[[仓库相对路径（不含 .md）|显示文本]]`；需要说明语义关系时，在原有 frontmatter 中合并 `relations`，保留其他字段和已有关系。
   - `citation`：正文直接引用或解释目标概念。
   - `similar`：有实质共同主题的相关笔记。
   - `subordinate`：源笔记属于目标概念的子主题。
   - `causal`：仅在已核实的来源明确支持因果关系时使用。
   - `status` 使用 `confirmed` 或 `inferred`；语义推断使用 `inferred`。
   - 每条结构化关系必须包含 `target`、`type`、`status`、`reason` 和 `evidence`。`target` 使用仓库相对路径含 `.md`，`reason` 说明关系，`evidence` 写实际正文依据或来源。因果关系必须为 `confirmed`，且 `evidence` 包含已核实的来源 URL。
6. 不重复添加同一关系，不添加自关联，不为制造反向边修改目标笔记：现有图谱会计算双向邻接和反向链接。标签可以辅助检索，但默认图谱隐藏标签，不能用标签代替概念笔记节点。
7. 完成后运行现有图谱解析器，确认新增节点被收录、目标路径可解析、新增关系无悬空链接。例如在仓库根目录执行：

   ```sh
   node --input-type=module -e 'import { readVault } from "./.vitepress/vault/build.mjs"; const vault = readVault(process.cwd()); console.log(`图谱解析成功：${vault.notes.length} 个节点，${vault.links.length} 条关联`);'
   ```

   再检查本次新增笔记和概念节点对应的 `notes`、`links`，核对每条预期关联的目标和关系类型。若已有无关错误阻止校验，说明具体限制，不宣称校验通过。
8. 向用户简要报告复用的节点、新建的节点和建立的关联，以及验证结果。

结构化关系示例（目标必须先实际存在，证据必须替换为笔记中的实际内容）：

```yaml
relations:
  - target: 计算机与软件/人工智能/检索增强生成.md
    type: subordinate
    status: inferred
    reason: 本笔记讨论检索增强生成中的分块策略。
    evidence: 正文说明分块大小影响检索上下文的完整性。
```
