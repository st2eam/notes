# 实战：为笔记建立可追溯问答

> 前置：完成[AI 学习路线](./学习路线.md)的基础和数据与质量阶段。目标：跑通清洗、检索、引用、权限和离线评测。最后核对：2026-09-29。

本实战在本地对 Markdown 笔记做**抽取式问答**：只返回匹配片段及其来源，不调用在线模型。这样可以先验证检索与引用链路。要加入生成式回答时，使用下文标注的接口伪代码替换最后一步，并继续验证来源支持度。

## 运行示例

仓库根目录中的 examples/notes_qa.py 使用 Python 3 标准库。执行：

~~~sh
python3 examples/notes_qa.py "什么是 Embedding"
python3 -m unittest discover -s tests -p 'test_notes_qa.py'
~~~

程序读取公开的 AI 章节 Markdown 文件，切分标题和正文，记录文件路径与行号，用简单词项匹配挑选片段。它是小规模教学基线，不是生产检索系统，也不把网页文本当工具指令。

## 从输入到结果

1. **数据处理**：只扫描允许公开的目录，给片段保存路径、标题、行号和版本线索。跳过空白片段。
2. **权限**：在搜索前过滤不可读取的文档。示例数据均为公开笔记；新增私人笔记时必须由服务端身份系统执行过滤，不能依赖前端隐藏。
3. **检索**：用确定性词项分数排序；无匹配时返回“没有找到足够证据”，不能编造答案。
4. **引用**：展示原文摘录与路径。引用应该指向实际参与回答的片段。
5. **评测**：固定问题和期望来源，检查“预期文件是否进入结果”、无匹配时是否拒答、权限过滤是否生效，并记录耗时。

~~~text
问题 → 权限过滤 → 索引中的候选片段 → 排序 → 摘录 + 来源
                                             ↓
                                 任务集检查与失败记录
~~~

下面是**厂商无关的模型接口伪代码，不能直接运行**。只有在检索和权限检查都通过后，才把证据交给模型：

~~~python
evidence = search_allowed_chunks(user, question)
if not evidence:
    return "没有找到足够证据"
answer = model.generate(
    task="仅根据证据回答；无法支持的部分说明不知道",
    question=question,
    evidence=[{"text": item.text, "source": item.path} for item in evidence],
)
return verify_citations_and_render(answer, evidence)
~~~
