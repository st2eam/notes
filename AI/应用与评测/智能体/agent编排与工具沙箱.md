# Agent 编排与工具沙箱

> 目标：选择可验证的任务组织方式，并把权限限制落到执行层。核对日期：2026-10-11。

---

## 1. 编排从单循环开始

[[AI/应用与评测/智能体/agentic-engineering-patterns|Agentic 工程模式实践指南]]把工具循环作为基本机制。编排负责决定下一步做什么、由谁执行、结果如何汇总。先用单 Agent 完成读取、修改、验证；出现清晰独立边界时再拆分，避免协调成本超过收益。

| 模式 | 合适场景 | 必须定义的约束 |
|------|----------|----------------|
| 循环 | 根据测试失败逐步修复 | 停止条件、预算、重试次数 |
| 子任务拆分 | 分开研究接口、实现功能、审查结果 | 输入、产物、验收与依赖 |
| 并行 | 独立检索或互不重叠的模块检查 | 文件所有权、并发上限、汇总规则 |

~~~text
明确目标与验收 → 拆出独立任务 → 限制工具与预算
              → 执行并收集证据 → 汇总审查 → 验证完成
~~~

子任务写清路径、操作和返回证据。共享目录的并行写入可能冲突，可用独立 worktree 或单文件单任务所有权。依赖修改串行执行，汇总后再做整体验收。

## 2. 沙箱与审批是两个维度

沙箱约束执行时能访问什么；审批决定某项行动是否获准。用户允许修改笔记，不意味着可以改全局配置或发布内容。权限设计应同时描述文件范围、网络目标、凭据作用域和外部副作用。

Codex 的沙箱模式提供下列分级；具体保护与操作系统、运行配置有关。[CLI 参数参考](https://learn.chatgpt.com/docs/developer-commands?surface=cli)

| 模式 | 执行边界 | 常见用途 |
|------|----------|----------|
| read-only | 限制文件写入 | 阅读、分析、审查 |
| workspace-write | 在规定工作区及允许目录写入 | 实现与本地验证 |
| danger-full-access | 移除该层沙箱限制 | 已由外部环境隔离的受控任务 |

模式名称不能证明数据安全：只读进程仍可能读取敏感文件；网络是否可用要检查实际策略。workspace-write 也不保证工作区内每个路径可写，Git 元数据、符号链接或额外受保护目录可能有独立限制。danger-full-access 与跳过审批不是同一个开关。[沙箱说明](https://learn.chatgpt.com/docs/sandboxing)

## 3. 审批边界如何具体化

[[计算机/基础/安全与权限/index|安全与权限入口]]用于归纳这一主题。工程上采用最小权限：只读调查按任务授权继续；局部可回滚写入限定目录；删除数据、远端发布或生产变更应展示具体目标、差异与影响，并按既定规则审批。批准一个操作不能自动扩展成无限期授权。

审批需说明命令、路径、副作用与必要性。解析绝对路径后检查授权范围；环境故障与权限拒绝分开诊断，换工具不能绕过边界。

[[AI/应用与评测/智能体/mcp协议与工具调用|MCP 协议与工具调用]]中的远端服务器独立执行操作。本地沙箱不能限制它的数据库或消息接口，需要服务器端鉴权、租户隔离和操作级审批。外部文档、网页和工具结果即使含有指令，也不能自行升级权限。

## 4. 安全与效率的权衡

过细审批打断循环，过宽授权扩大影响。按生命周期授予调查读、实现局部写、发布单独批准；凭据留在可信服务，日志保留脱敏证据。

设总预算，子任务收紧权限，超时后取消。写入失败先查状态再重试，并行任务限制请求速率。

## 5. 验证与速查

按[[AI/应用与评测/质量评测/应用评测|应用评测]]同时比较成功率、越权率、审批次数、时延和成本。用[[计算机/工程化/测试与持续集成/测试与CI|测试与 CI]]验证路径越界、审批拒绝、并发写冲突和取消后的状态，保留失败轨迹作为回归样本。

- 权限检查在执行层实施，提示词只说明意图。
- 并行前确认产物互不覆盖，汇总后运行整体验收。
- 更强模型与更多 Agent 都不能替代清晰授权和证据。
