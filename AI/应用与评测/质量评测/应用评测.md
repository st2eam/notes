# AI 应用评测：知道改动是否更好

> 前置：[概率统计与实验](/%E6%95%B0%E5%AD%A6%E4%B8%8E%E7%BB%9F%E8%AE%A1/%E6%A6%82%E7%8E%87%E4%B8%8E%E5%AE%9E%E9%AA%8C/%E6%A6%82%E7%8E%87%E7%BB%9F%E8%AE%A1.md)、[测试与 CI](/%E8%AE%A1%E7%AE%97%E6%9C%BA%E4%B8%8E%E8%BD%AF%E4%BB%B6/%E5%B7%A5%E7%A8%8B%E5%8C%96/%E6%B5%8B%E8%AF%95%E4%B8%8E%E6%8C%81%E7%BB%AD%E9%9B%86%E6%88%90/%E6%B5%8B%E8%AF%95%E4%B8%8ECI.md)。目标：建立任务集、区分检索与回答指标、读懂混淆矩阵。最后核对：2026-09-29。

演示中的几个漂亮回答无法代表实际质量。先定义“成功”的可观察证据，再收集覆盖常见情况、边界情况和恶意输入的样本。保留原始输入、期望结果、实际结果和系统版本，才能回看退步发生在哪一步。

## 先拆开评测对象

| 层次 | 示例指标 | 常见失败 |
|------|----------|----------|
| 检索 | 期望来源进入前 K 条的比例、来源覆盖 | 找错文档、漏掉精确术语 |
| 回答 | 正确性、引用支持度、拒答是否恰当 | 无证据却编造、引用不支持结论 |
| 工具 | 是否选对工具、参数与权限 | 调错工具、重复写入、越权 |
| 系统 | 时延、费用、错误率、隐私 | 超时、重试副作用、敏感信息泄露 |

下面的实验台使用八个固定样本。改变阈值会影响精确率和召回率；哪一项更重要取决于误报与漏报的业务代价。

<EvalMatrixLab />

一个最小**可运行 Python 3 计算例子**：

~~~python
truth = [1, 0, 1, 0]
score = [0.9, 0.8, 0.4, 0.1]
threshold = 0.5
prediction = [int(value >= threshold) for value in score]
tp = sum(p == 1 and y == 1 for p, y in zip(prediction, truth))
fp = sum(p == 1 and y == 0 for p, y in zip(prediction, truth))
fn = sum(p == 0 and y == 1 for p, y in zip(prediction, truth))
precision = tp / (tp + fp) if tp + fp else 0
recall = tp / (tp + fn) if tp + fn else 0
assert (tp, fp, fn, precision, recall) == (1, 1, 1, 0.5, 0.5)
~~~

## 从失败建立回归集

先收集 30–50 个问题，给每个问题写期望来源、验收标准和重要程度。检索失败、引用错误、权限失败、工具失败分别记录；同一个问题可以有多次运行，因为模型输出有随机性。修改提示、索引或工具后，对同一任务集运行旧版和新版，比较成功率、时延和费用，再人工检查争议案例。

自动评分能加速回归检查，但评分规则也可能有漏洞。关键结论采用规则检查、人工复核和运行轨迹结合。公开基准分数不能代替自己产品的验收集。

参考：[Anthropic Agent 评测方法](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)、[OWASP LLM 风险清单](https://genai.owasp.org/llm-top-10/)。
